## 무한 발굴 / 실시간 발굴 (개편)
- ✨ **무한 발굴(5곳)**: 후보가 바닥나면 **① 지금 조건 → ② 같은 권역 → ③ 전국 → ④ 이미 본 곳** 순으로
  자동으로 넓혀서 멈추지 않는다. 화면에 "같은 권역까지 넓혀 발굴했어요"처럼 단계가 표시된다.
- ⚖️ **지방 가중치**: 권역별 등록 수가 적을수록 발굴 확률을 높인다(`areaBoost`) — 서울만 계속 나오지 않게.
- 📡 **실시간 발굴(다중 소스)**: OSM Overpass(2개 미러) → 실패 시 Nominatim. 분류(중식·분식·일식)를 고르면
  `cuisine=chinese|noodle|dumpling` 같은 **음식 태그로 한 번 더** 훑는다.
- 🔗 발굴 패널에 **다이닝코드 랭킹 / 캐치테이블 검색 / 네이버지도** 링크가 붙어, 지금 고른 지역·분류를 바로 이어서 볼 수 있다.
  (다이닝코드·캐치테이블은 CORS·WAF 때문에 브라우저 JS가 HTML을 직접 못 읽는다 — 사전 수집 + 검색 링크로 정직하게 처리)

## 그 밖에
- 🆕 신상 맛집 29곳(2025~26) · 🕓 확인일(`v`) 기준 1년 지난 항목 자동 제외

## 빌드
```bash
python3 data/dc/tsv2json.py                # 다이닝코드 TSV → data/regional-places.json
python3 build.py                           # template.html + data/* → index.html
python3 check_syntax.py                    # ESprima 문법 검사
```

## 데이터 갱신 규칙
1. 새로 확인한 가게는 `data/new-places.json`(지도 실존 확인) · `data/new-open-2026.json`(신상) ·
   `data/regional-places.json`(지역 랭킹)에 넣고 `v`에 확인일을 적는다.
2. 기존 항목의 가격·영업시간을 다시 확인했으면 `data/verify.json`의 `overrides`에 최신값을 적는다.
3. 확인 불가·폐업 항목은 `data/verify.json`의 `drop`에 이유와 함께 적는다.
4. `v`가 1년을 넘으면 빌드가 자동으로 빼고 목록을 출력한다.
